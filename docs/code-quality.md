# 코드 품질 기준

이 문서는 저장소가 자동으로 검사하는 코드 품질 기준을 정의한다. 모든 변경은 로컬 검사와 CI 검사를 통과해야 병합할 수 있다.

## Rust 툴체인

`rust-toolchain.toml`은 Rust 1.100.0과 다음 구성 요소를 고정한다.

- `rustfmt`
- Clippy

개발자와 CI는 `rustup`이 선택한 프로젝트 툴체인을 사용한다. 다른 Rust 버전에서만 통과하는 변경은 병합하지 않는다.

## 필수 검사

모든 커밋은 해당 작업 단위에 필요한 검사를 통과해야 한다. PR은 다음 전체 검사를 통과해야 한다.

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps
cargo deny check
```

`cargo fmt`가 파일을 바꾸면 포맷 검사에 실패한다. Clippy 경고와 rustdoc 경고도 빌드 실패로 처리한다.

## 컴파일러 규칙

루트 `Cargo.toml`은 Rust와 Clippy lint를 workspace 단위로 설정한다. 모든 패키지는 해당 설정을 상속한다.

다음 항목은 오류로 처리한다.

- 안전하지 않은 코드
- 사용하지 않는 결과와 import
- 도달할 수 없는 코드
- 디버그 출력
- `unwrap`과 `expect`
- `panic!`, `todo!`, `unimplemented!`
- 잠금을 잡은 채 실행하는 `await`
- 정수의 의미 없는 캐스팅과 잘림 가능성이 있는 캐스팅
- 와일드카드 import
- 문서에 없는 `unsafe` 블록

테스트도 같은 lint 정책을 따른다. 실패가 테스트 오류 자체인 경우에만 `expect`를 제한적으로 허용할 수 있다. 허용할 때는 가장 작은 표현식에 `#[allow]`를 붙이고 이유를 적는다.

## 타입과 오류 처리

외부 입력은 경계에서 검증한 후 도메인 타입으로 변환한다. URL, 포트, 요청 ID, 세션 ID를 검증되지 않은 문자열이나 정수로 내부에 전달하지 않는다.

공개 함수는 호출자가 처리할 수 있는 오류 타입을 반환한다. 라이브러리 코드는 정상적인 실패에 `panic!`, `unwrap`, `expect`를 사용하지 않는다.

열거형은 상태를 빠짐없이 표현한다. 진행 중, 완료, 실패, 취소, 불완전 상태를 불리언 조합으로 나타내지 않는다.

## 함수와 모듈

함수는 한 가지 책임을 가진다. 함수가 파싱, 저장, UI 갱신을 함께 처리하면 책임별로 나눈다.

다음 값은 검토 신호다.

- 인수가 5개를 넘는 함수
- 80줄을 넘는 함수
- 중첩 깊이가 4단계를 넘는 코드
- 하나의 파일에 서로 다른 소유권을 가진 상태가 함께 있는 구조
- 같은 상태를 쓰는 모듈이 둘 이상인 구조

검토 신호는 자동 면제 사유가 아니다. 먼저 타입이나 소유권을 다시 설계한다.

## 주석과 문서

코드가 이름과 타입만으로 설명할 수 없는 제약이 있을 때만 주석을 작성한다. 주석은 코드가 무엇을 하는지 반복하지 않는다.

다음 내용을 주석으로 남길 수 있다.

- 프로토콜 사양 때문에 필요한 비직관적 처리
- 안전성 불변식
- 운영체제 API의 제약
- 경쟁 상태를 막기 위한 순서

구현을 읽으면 알 수 있는 내용을 설명하는 주석은 작성하지 않는다. 오래된 주석은 잘못된 코드보다 발견하기 어렵다.

공개 API 문서는 호출 계약, 오류, 보안 영향을 설명한다. 내부 함수는 이름과 타입으로 계약이 드러나면 별도 문서를 요구하지 않는다.

## 테스트 기준

테스트는 외부 사용자가 관찰하는 동작을 검증한다. 비공개 함수 호출 순서나 내부 자료구조는 검증하지 않는다.

프록시 테스트는 다음 동작을 실제 TCP 연결로 확인한다.

- HTTP 요청이 업스트림 서버에 도착한다.
- 업스트림 응답이 클라이언트에 도착한다.
- `CONNECT` 터널이 양방향 바이트를 전달한다.
- 잘못된 대상과 연결 실패가 정의된 오류로 끝난다.
- 종료 요청 후 리스너가 새 연결을 받지 않는다.

각 버그 수정은 재현 가능한 회귀 테스트를 포함한다. 시간이나 네트워크 상태에 의존하는 테스트에는 명시적인 제한 시간을 둔다.

## 의존성 기준

새 의존성은 표준 라이브러리나 기존 의존성으로 해결할 수 없는 기능에만 추가한다. PR 설명은 새 크레이트의 역할을 적는다.

`cargo-deny`는 다음 항목을 검사한다.

- 알려진 보안 취약점
- 허용하지 않은 라이선스
- 알 수 없는 Git 의존성
- 같은 크레이트의 불필요한 중복 버전

기본 기능은 필요한 경우에만 사용한다. 사용하지 않는 기능을 끄면 빌드 시간과 공격 가능한 코드가 줄어든다.

## CI와 병합 기준

CI가 실패한 PR은 병합하지 않는다. 검사 비활성화, 광범위한 `allow`, 테스트 삭제로 CI를 통과시키지 않는다.

예외가 필요하면 가장 작은 범위에 적용한다. 코드에는 예외 이유를 적고 PR에는 제거 조건을 적는다.
